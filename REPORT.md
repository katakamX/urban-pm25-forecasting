## Abstract

Urban particulate pollution exhibits temporal dependence, seasonal structure and abrupt episodes driven by meteorology, emissions and regional transport. This project develops a daily PM2.5 forecasting benchmark for Bengaluru and Delhi using the *Air Quality Data in India (2015–2020)* dataset compiled from CPCB observations. The study compares a statistical time-series model (ARIMA), recurrent neural networks (GRU, LSTM and bidirectional LSTM), and a gradient-boosted tree model (XGBoost). Forecasts are evaluated at 1-, 7- and 14-day horizons using chronological rolling-origin evaluation. MAE and RMSE are treated as primary metrics, with sMAPE and R² as supplementary measures. The pipeline includes date normalization, city filtering, duplicate aggregation, conservative short-gap interpolation, training-only imputation, and recursive multi-step prediction where applicable. The project also examines why univariate models may fail during abrupt pollution episodes and why performance can differ between a southern peninsular city and a northern Indo-Gangetic city. Numerical results are generated by running the included code on the downloaded source dataset; no results are pre-filled or fabricated.

**Keywords:** PM2.5, air quality forecasting, ARIMA, GRU, LSTM, BiLSTM, XGBoost, Bengaluru, Delhi, time series.

## 1. Introduction

Fine particulate matter (PM2.5) consists of particles with aerodynamic diameter of 2.5 micrometres or less. Due to their ability to penetrate deep into the respiratory system, elevated PM2.5 concentrations are an important urban environmental and public-health concern. Forecasting daily concentrations can support preparedness, public communication and pollution-management planning.

Air quality is not governed by emissions alone. Wind speed and direction, rainfall, atmospheric stability, boundary-layer height, temperature inversions, regional transport, seasonal activity and local sources all affect measured concentrations. These drivers create both predictable seasonal patterns and abrupt changes.

This project compares two contrasting urban settings:
- **Bengaluru:** a southern peninsular metropolis where rainfall, local traffic, construction and urban activity can contribute to variable particulate levels.
- **Delhi:** a northern city where post-monsoon and winter episodes can be pronounced, with meteorology and regional emissions potentially contributing to sharp peaks.

The analysis uses a historical daily city-level dataset. It is a controlled model-comparison exercise, not a live pollution warning service.

## 4. Methodology

### 4.1 Data preprocessing

1. Read the daily CSV and validate the `City`, `Date` and `PM2.5` fields.
2. Normalize Bangalore/Bengaluru naming to a single city label.
3. Parse dates and convert PM2.5 to numeric values.
4. Treat negative concentrations as invalid.
5. Aggregate duplicate city-date rows using the median.
6. Reindex each city to a complete daily calendar.
7. Interpolate only short interior gaps of at most three consecutive days.
8. Leave longer gaps missing until a training prefix is formed; fill them using that prefix's median only. This prevents future information from influencing imputation.

### 4.2 Train/test strategy

A chronological 80:20 split is used. The final 20% is the test interval. Multiple forecast origins are sampled evenly from the test interval. At each origin, the model receives only the observations available up to that date and forecasts the next 14 days. Forecasts are scored only on dates where the original PM2.5 target is observed.

This rolling-origin design is more representative of real forecasting than random train/test splitting. It also prevents future target values from entering lag features or recursive forecasts.

### 4.3 Forecast horizons and metrics

For every model, the first 1, 7 and 14 forecast leads are evaluated.

- **MAE:** average absolute prediction error; directly interpretable in µg/m³.
- **RMSE:** penalizes large errors more strongly and is sensitive to missed peaks.
- **sMAPE:** symmetric percentage error; can still be unstable when both actual and predicted values are near zero.
- **R²:** supplementary goodness-of-fit statistic; it can be negative on a difficult forecast interval.

Lower MAE and RMSE indicate better performance. Metrics should be interpreted separately by city and horizon.

### 4.4 Models

**ARIMA — Autoregressive Integrated Moving Average**

ARIMA models linear relationships between past values and forecast errors after differencing where required. A small candidate set of (p,d,q) configurations is fitted at each forecast origin. The model with the lowest AIC is selected from the successful candidates. ARIMA is a useful statistical baseline but may struggle with nonlinear dynamics and abrupt regime changes.

**GRU — Gated Recurrent Unit**

GRU is a recurrent neural network that uses update and reset gates to control information flow. It can learn temporal dependencies with fewer gates and often fewer parameters than an LSTM. It uses the preceding 30 days to predict the next 14 days.

**LSTM — Long Short-Term Memory**

LSTM uses input, forget and output gates with a cell state to retain information over longer sequences. It is trained on 30-day input windows and outputs a 14-day vector.

**BiLSTM — Bidirectional LSTM**

The bidirectional model processes the historical 30-day input sequence in both directions. This can learn patterns from both ends of the observed input window. It does not use future target observations; bidirectionality is confined to the known historical window.

**XGBoost**

XGBoost is a gradient-boosted decision-tree model. The feature set includes PM2.5 lags (1, 2, 3, 7, 14, 21 and 30 days), rolling means and standard deviations, weekday, month and annual sine/cosine terms. Multi-step forecasts are recursive: each predicted value becomes an input lag for the next step.

**Baselines**

- Persistence: repeat the most recently observed PM2.5 value.
- Seasonal naive: repeat the most recent weekly pattern.

A complex model is not automatically superior. It should be considered useful only if it consistently improves on the baselines.

## 6. When and why models fail

### 6.1 Abrupt pollution episodes

A univariate model observes past PM2.5 but does not know that a new fire episode, traffic disruption, dust event or regional transport event is occurring. Delhi's winter and post-monsoon pollution episodes can be driven by multiple interacting factors. Without fire counts, wind, rainfall, temperature, boundary-layer height and regional transport variables, the model may underpredict sudden peaks.

### 6.2 Meteorological regime changes

Rain can remove particles from the atmosphere, while stagnant conditions and low mixing heights can allow pollutants to accumulate. A model trained only on pollutant history cannot anticipate a sudden weather change. This limitation can affect both cities, although the seasonal context differs.

### 6.3 Forecast horizon

As the horizon increases, the forecast depends less on the most recent measured value and more on learned average patterns. Recursive XGBoost may accumulate errors because predicted values become future lags. Neural models can regress toward common training values when uncertain. ARIMA forecasts may converge toward a long-run level depending on the fitted order and differencing.

### 6.4 Data quality and coverage

Long gaps, changing monitor coverage and city aggregation can distort seasonal patterns. Interpolation can smooth real peaks if applied across long gaps; therefore this project restricts interpolation to short interior gaps and reports missingness.

### 6.5 Model complexity and sample size

Deep recurrent models have more parameters than a compact statistical model. With only a few years of daily observations, a neural network may overfit, particularly when the number of valid training windows is reduced by missing data and the 30-day input/14-day output design.

## 7. Discussion

The main comparison should be based on the generated per-city/per-horizon metrics and diagnostic plots. The best model may differ by city and forecast horizon. There is no defensible reason to assume that one architecture will dominate all settings before evaluating it.

A useful interpretation distinguishes:
1. **Predictability:** whether a city has stable temporal structure.
2. **Peak sensitivity:** whether the model captures high-concentration episodes.
3. **Horizon robustness:** how rapidly error grows from day 1 to day 14.
4. **Baseline improvement:** whether complexity produces a practical gain over persistence or weekly repetition.

The historical dataset enables a controlled comparison but does not support causal attribution of individual pollution events.

## 8. Conclusion

This project provides a reproducible comparison of ARIMA, GRU, LSTM, BiLSTM and XGBoost for daily PM2.5 forecasting in Bengaluru and Delhi. Its main methodological safeguards are chronological rolling-origin evaluation, training-only imputation/scaling, recursive multi-step prediction and baseline comparisons. The generated results should be used to identify which model is most reliable for each city and horizon. The analysis also demonstrates a central limitation of univariate forecasting: historical PM2.5 alone cannot anticipate external drivers such as meteorology, fires, transport and sudden emission changes.
